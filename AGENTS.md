- Discord auto-linking (server join, voice join, post-match DMs; never public claim buttons) lives in `public/spotbot/auto-link.cjs`; profiles are global so a link in one server applies everywhere.
- Scouting stats split current EA FC season vs older seasons in `recruitment.statsFor`; season start comes from `FC_SEASON_START` env so a new game needs no code change.
- Players holding a position role are auto-added to the club roster (`roster.syncMemberPositions`, on role change and at startup); multi-club servers match by club name in a role, clubs opt out with `auto_roster: false`.
- Both the cloud sync (sync-ea-stats) and the bot relink pre-FC27 clubs by exact EA name and mark them ea_fc_version='fc27'; FC27 gave every club a new ID, so old IDs only return last season's matches.
- Bot database access goes through the `bot-proxy` function with a shared BOT_PROXY_SECRET; the admin key never leaves the backend.

- Guild-authorized player-cards latest shares signed fronts for app/broadcast reuse; backs/collections stay owner-only. Recaps label single-match ratings separately from collection stats; the recap image backdrop is only ever an original pro-photo upload (`source_kind='upload'`) from a match player, never generated art, and the recap text stays compact, adding only what the image doesn't show.
- Event announcement mentions are enabled only in postEvent; board updates and reposts suppress mentions so availability changes never notify the whole server again.
- Pro photos are ingested only through the `pro-photo` function (bot secret, AI vision check, private storage with long-lived signed URLs); every accepted upload is retained in `pro_photo_assets`, while `pro_photos` stays as the latest-photo compatibility record.
- Photo management in `pro-photo/manage.ts` requires the bot-authenticated requester to equal the owner, deletes only original uploads and their storage objects, and refreshes the compatibility photo; `/me` controls bind to the clicking user so saved cards stay untouched.
- The bot requests Discord's Message Content intent (needed to see attachments for #pro-photos) and falls back to logging in without it if the portal toggle is off, so a missing toggle never takes the bot offline.
- `fun-zone.cjs`: real-stat roasts, fiction-marked rumours.
- Season sets: `player_season_archive` (never purged) feed backs (`graphics-card-back.cjs`) plus exact-club EA total.
- Hidden EA stats come from match_event_aggregate codes, decoded identically in ea-player-stats.cjs and backfill_advanced_player_stats() (hourly); codes follow the refined OurProClub mapping in docs/ea-event-codes.md (deduplicated hockey assists, derived net possession and defensive stops), always shown as estimates.
- Graphics Studio rules live in public/spotbot/AGENTS.md.
- Club-art filters original uploads before limiting queries and sends a stable face anchor before pose references; generated assets are display-only to prevent cumulative likeness drift.
- Recruiting artwork is aspect-fitted in a separate lettering-free region with decorative frames behind it, so generated groups are never cropped or covered by poster bands.
- The /setup wizard (button → one modal in `club-setup.cjs`) saves EA link, accent colour and `club.kit` through the same helpers as /setclub and /brand, so onboarding never diverges from the individual commands.
- The stats panel (sticky, in `club-stats.cjs`) lives in each club's `stats_panel_channel_id` falling back to `stats_channel_id` (opt out with `stats_panel: false`); Team Stats and EA Member List read EA live so they always match EA's own numbers.
- Discord OAuth on gafferbot.app runs in the Cloudflare Worker (`worker/index.ts`, `/api/auth/discord`) with Worker secrets; Lovable-hosted previews fall back to the `auth-discord` function, so production sign-in has no Lovable Cloud function dependency.
- All backend functions (except Worker-hosted Discord OAuth) are bundled by `scripts/build-local-functions.mjs` into `public/spotbot/local-functions/`; the self-hosted bot runs them in-process, serves them on FUNCTIONS_PORT for the web app via the Worker's `/api/functions/v1/*`, and routes Lovable AI gateway calls to the server's own keys (images and strict-JSON vision to OpenAI, plain chat to Gemini then Claude), so nothing depends on Lovable Cloud. Re-run the script after editing functions.
- Self-hosted scheduled jobs (EA syncs, stats/archive refreshes, monthly cleanup) run in `public/spotbot/scheduler.cjs` inside the bot when it has no BOT_PROXY_SECRET, replacing database cron so the server needs no cloud scheduler; SCHEDULER=off disables.
- The MCP server for AI assistants is the `gafferbot-mcp` function, served at gafferbot.app/mcp by the Worker; it is read-only, acts as one Discord user (personal `gb_` tokens from /me → AI Assistant via `mcp-token`, hashed in `mcp_access_tokens`, or a web session) and checks `guildAccessLevel` per server, so a token never sees servers its player can't.
- Newspaper match reports (`buildMatchReport` in `chronicle.cjs`, autopilot job `press`) print one Chronicle-style story per game in the club's `chronicle_channel_id` only, after the regular recap; clubs without a picked Chronicle channel get none, so recap channels never double up. Postgame pieces (match report and recap) talk about that one game only, with varied phrasing and puns from `press-copy.cjs`; the run, streaks, head-to-head, milestones and season storyline belong to the Chronicle editions.
- The web Control Room (`/control`, `src/pages/ControlRoomPage.tsx`) runs every /manager and /me panel action through `public/spotbot/web-panels.cjs` via the `web-panel` function: it builds an interaction as the user's real Discord member and calls routeInteraction, so new panel actions appear on the web with no extra code and the same permission checks apply.
- The Chronicle editions (3 PM, midnight) cover the day plus the recent run and season storyline, and on graphics-enabled clubs carry a front-page image (`G.frontPage` via `broadcast.editionImage`) that shows each cover player as their rendered player-card art (Studio `generated` assets made from their own reference photos), falling back to their own original upload; the recap backdrop stays upload-only. Bundled sample art for Studio style menus lives in `assets/samples` and is never used on real posts.
- Per-club identity (`club.identity`, `public/spotbot/club-identity.cjs`): newspaper voice preset, paper name, hometown and opponent name gags drive the Chronicle, match reports, the AI writer's tone and the Fun Zone. Clubs pick them in /setup → Club identity (also on the web via the Control Room's Setup Wizard); unset clubs keep the original Italian (Palermo) voice. Never hard-code a club's flavour in shared code; add a voice preset or identity field instead (press-copy.cjs lines with Italian words only run for the Italian voice).
- Match tags (`match-tags.cjs`): managers mark played games League, Tournament or BYOT (Manager Hub or Stats & Scouting → Tag Matches, also in the Control Room); EA friendlies played during a BYOT, tournament or league event are tagged automatically. The tag lives in `club_matches.match_data._tag` (EA syncs only insert, so it survives), and everything reads it through `matchCompetition()` / `InsightMatch.competition` in `src/lib/clubInsights.ts` (rebuild with `npm run build:bot-lib`), so stats filters, recaps, the Chronicle and the web app agree.
